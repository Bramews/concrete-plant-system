# 23. الأداء والاختناقات (Performance, Bottlenecks, & Optimizations)

نظام سحابي يخدم مئات المحطات وآلاف الموظفين سيواجه مشاكل حتمية في الأداء إذا لم يُصمم بعناية.

## 1. اختناقات الشبكة والـ Polling (Network Bottlenecks)
- **المشكلة الحالية:** استعلام المتصفح كل ثانية عن حالة الخلاط أو جلب أحدث الطلبيات يرهق السيرفر ويرهق اتصال قاعدة البيانات (Connection Pool).
- **الحل الجذري (WebSockets / SSE):** 
  - لا تجعل العميل يسأل السيرفر. اجعل السيرفر يرسل للعميل فقط عندما يحدث تغيير حقيقي (Event-Driven).
  - إذا تم استخدام WebSocket Server (مثل Socket.io أو Pusher)، السيرفر يستهلك موارد أقل بـ 90% من الـ HTTP Polling المستمر.

## 2. عنق زجاجة قاعدة البيانات (Database Locking & Slow Queries)
- **جدول الحركات (InventoryTransaction):**
  - كما ذكرت، هذا الجدول سيحتوي ملايين الأسطر. 
  - **خطأ الأداء:** جمع كل السطور `SUM()` لمعرفة المخزون في كل Request. 
  - **التحسين (Optimization):** جدول `Material` يحوي حقل `stock`. عند إدراج حركة مخزون جديدة، استخدم Database Trigger أو `$transaction` سريع لتعديل الـ `stock` كمتغير كاش، وبذلك تتم القراءة من حقل واحد مباشرة بسرعة البرق `O(1)`.
- **فهرسة الطلبيات (Indexing Orders):**
  - شاشة المشغل تطلب دائماً "الطلبات التي حالة = LAB_APPROVED". وضع Index مركب (Composite Index) على `[companyId, status]` سيجعل الـ Query تنفذ في أقل من 5ms بدلاً من البحث في مئات آلاف الطلبات المؤرشفة.

## 3. أداء الواجهة الأمامية (Frontend Render Performance)
- **الرندرة المزدوجة (Re-rendering):**
  - في صفحة المشغل، إذا تغير الميزان من 100 كغ إلى 101 كغ، لا ينبغي أن يتم عمل Re-render للقائمة الجانبية (Sidebar) ولا للطلبيات (Orders).
  - **التحسين:** استخدم `React.memo` و `useMemo` و `useCallback`. اجعل مكون `LiveGauge` يقرأ بياناته من الـ State الخاص به فقط، أو من Context مخصص للموازين مفصول تماماً عن Context الطلبيات.
- **مشكلة الـ Hydration:**
  - عرض التوقيت الحالي في الـ Server Component سيسبب Mismatch مع المتصفح. 
  - **التحسين:** استخدام `suppressHydrationWarning` أو إظهار الوقت فقط بعد `useEffect(() => setMounted(true), [])`.

## 4. المهام الخلفية وقوائم الانتظار (Background Jobs & Queues)
- **طباعة التقارير المعقدة:** 
  - عندما يطلب مالك الشركة كشف حساب ومبيعات لمدة سنة كاملة، هذه العملية قد تستغرق 10 ثوانٍ لحسابها. 
  - إذا استدعيت بـ Server Action عادي، سيعلق المتصفح أو يحصل Vercel Timeout (الحد 10 ثوانٍ مجاناً).
  - **التحسين:** استخدام Message Queue (مثل RabbitMQ أو BullMQ). إرسال طلب التقرير للخلفية، والرد فوراً للمستخدم "جاري تجهيز التقرير"، ثم إرسال Notification له حين يكتمل التحميل لملف PDF جاهز.

## 5. الذاكرة المخبئية (Caching Strategy)
- واجهة ה-ERP (مثل قائمة العملاء، أو قائمة المواد، أو أسعارها) لا تتغير كل دقيقة.
- استخدام ميزة `Next.js Data Caching` أو `revalidateTag` أو `Redis` لجلب قائمة العملاء. 
- وبمجرد قيام המبيعات بإضافة عميل جديد، نستدعي `revalidatePath('/customers')` لمسح الكاش وتحديثه، مما يخفف الحمل عن Prisma و Database.
