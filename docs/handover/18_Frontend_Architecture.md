# 18. الواجهة الأمامية (Frontend Architecture)

واجهة المستخدم مبنية بـ **React (Next.js App Router)**. وهي مقسمة لقسمين: قسم الـ ERP (شاشات بيضاء نظيفة مثل Vercel) وقسم ה-SCADA (واجهة المشغل - الصناعية، السوداء). سأركز هنا على هندسة واجهة المشغل لأنها الأكثر تعقيداً.

## 1. فلسفة المكونات (Component Philosophy)
الواجهة لا تعمل كصفحة واحدة متجانسة، بل كـ "شظايا" (Fragments) ذكية ومستقلة:
- شاشة المشغل تظل مفتوحة لـ 12 ساعة متواصلة. 
- يجب أن لا يتم عمل (Full Page Reload) إطلاقاً.
- أي إعادة تصيير (Re-render) للـ Root Component سيسبب وميضاً (Flicker) مزعجاً ويفقد الاتصال اللحظي للأنيميشن. 
- **الحل:** الدفع بالحالة (State) إلى أعمق مكون ممكن (Push State Down). ميزان الإسمنت لا علاقة له باسم السائق، لذلك لكل منهما State منفصل.

## 2. إدارة الحالة والأدوات (Hooks & Contexts)
- **`useState` / `useEffect`:** هي الأساس ללـ Client Components. 
- **`usePLC()` (Custom Hook مقترح):**
  - يستدعي اتصال WebSocket أو Polling مرة واحدة فقط في الـ Root.
  - يوفر البيانات `(waterWeight, cementWeight, mixerStatus)` לכל مكون طفل يطلبها.
- **`useContext(OperatorContext)`:**
  - يحتفظ بالطلبية المحددة حالياً (Selected Order) لأن الـ `BatchForm` يحتاجها، ومكون `TicketList` يحتاجها لتسليط الضوء على تذاكرها، دون الحاجة لتمريرها كـ `Props` عبر 10 مستويات.

## 3. التصميم و CSS (Tailwind & CSS Modules)
تم استخدام Tailwind CSS، ولكن لأن الواجهة صناعية، هناك متطلبات غير عادية (توهجات نيون، حدود زجاجية، خطوط أحادية).
- **ملف `operator.css`:**
  - يحتوي على فئات مخصصة لا يوفرها Tailwind الافتراضي بسهولة، مثل:
    - `.op-card`: خلفية داكنة جداً مع حدود شفافة (Glassmorphism).
    - `.op-glow-red`: تأثير نيون لامع يستخدم وقت الإنذارات.
  - **الخطوط (Fonts):** تم فرض `font-mono` (أو `tabular-nums`) على أي رقم يتحرك. الرقم "1" يأخذ نفس المساحة العرضية للرقم "8"، لكي لا يتمدد المربع وينكمش عند تغير الوزن.

## 4. الرسوميات والأنيميشن (SVG & Framer Motion)
لإنشاء مظهر الـ SCADA:
- **الصوامع (`ScadaSiloSVG.tsx`):** رسمت كـ SVG يدوي (Paths). تم ربط قيمة الـ `stock` بمتغير يغير الـ `Y` للـ Rectangle الذي يمثل سائل/بودرة المادة ليرتفع وينخفض.
- **الموازين الدائرية (`LiveGauges.tsx`):**
  - لا نستخدم مكتبات جاهزة ثقيلة مثل Chart.js.
  - نستخدم `<circle>` SVG، ونحرك `stroke-dashoffset` لعمل مؤشر دائري.
  - **Framer Motion:** تستخدم لجعل التغيير بين 100 كغ و 500 كغ يبدو كانزلاق سلس (Spring Animation) بدلاً من قفزات خشنة، مما يعطي شعوراً بفيزيائية الميزان الحقيقي.
- **الخريطة المضيئة (`ProcessFlow.tsx`):**
  - خطوط SVG تضاء برمجياً متزامنة مع حالة الخلاط لتمثيل حركة الإسمنت في الأنابيب.

## 5. مقاومة الأخطاء (Error Boundaries)
ماذا لو فشل كود في `LiveGauges` بسبب بيانات `null`؟ لا يجب أن تتحطم الشاشة كلها (شاشة الموت البيضاء في React) لأن المشغل لن يستطيع إيقاف الخلاط.
- كل Widget ضخم مغلف بـ `<ErrorBoundary>`. إذا تعطل الميزان، يظهر مكانه صندوق أحمر صغير "تعطل المقياس"، بينما يبقى زر "إيقاف الخلاط" فعالاً بجانبه.
