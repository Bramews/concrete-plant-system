# 🖥️ الفصل الثامن: تحليل الشاشات وواجهة المستخدم (Screens, UI, and Components)

هذا الفصل يشرح بتشريح دقيق كل شاشة يراها المشغل (Operator)، المكونات الموجودة داخلها، كل زر ماذا يفعل بالضبط، ومن أين تأتي البيانات.

## 1. الهيكل العام (Global Layout)
### `app/system/operator/layout.tsx`
- **سبب الوجود:** تغليف جميع صفحات المشغل لتوفير قالب موحد (Sidebar + Header + Footer). يمنع إعادة تحميل هذه العناصر عند التنقل بين الصفحات لضمان عدم انقطاع الاتصال الحي مع الـ PLC.
- **العناصر:**
  - الشريط الجانبي (`OperatorSidebar.tsx`).
  - الشريط العلوي (`OperatorHeader.tsx`).
  - مساحة المحتوى (`{children}`).

## 2. الشريط العلوي (OperatorHeader)
- **مؤشر الاتصال (ConnectionStatus):**
  - **آلية العمل:** يستخدم `navigator.onLine` كبديل مبدئي (ويجب أن يُربط بحالة اتصال الـ WebSocket لاحقاً).
  - **الألوان:** أخضر نابض (`bg-emerald-400`) للاتصال، أحمر نابض (`bg-red-400`) للانقطاع.
- **الساعة الرقمية:**
  - **المشكلة التي تم حلها:** خطأ عدم توافق الخادم والعميل (Hydration Error).
  - **الحل:** استخدام `useEffect` مع `mounted state` واستخدام `suppressHydrationWarning`.
- **زر ملء الشاشة (Fullscreen Toggle):**
  - يستخدم `document.documentElement.requestFullscreen()` لتوفير تجربة SCADA خالية من متصفحات ويندوز.

## 3. شاشة قمرة القيادة (Cockpit Page)
**المسار:** `/system/operator/cockpit/page.tsx`
**الهدف:** لوحة مراقبة مركزية تعطيك حالة المحطة في نظرة واحدة. لا تحتوي على أزرار تنفيذية خطيرة (باستثناء OneClickProduction).
### أ. شريط حالة الخلاط (`MixerStatusBar.tsx`)
- **حالاته (States):** `IDLE`, `WEIGHING`, `MIXING`, `DISCHARGING`.
- **البيانات:** يتم تحديث الحالة والـ `progress` بناءً على المؤقتات حالياً (كـ Mock/Simulation) ويجب ربطها لاحقاً بمتغيرات الـ PLC المباشرة (عبر Server-Sent Events أو WebSockets).
- **التفاعل:** لا يُنقر عليه، يعرض فقط.

### ب. لوحة الإنذارات (`AlarmPanel.tsx`)
- **البيانات:** مصفوفة من كائنات `Alarm` تحوي (مستوى، رسالة، توقيت).
- **زر (X - Dismiss):** يقوم بتنفيذ دالة تُصفي (filter) الإنذار من المصفوفة. (في بيئة الإنتاج، يجب أن يرسل API Call للـ Backend لتسجيل `Acknowledge` وإسكات صافرة الإنذار الفيزيائية).

### ج. خريطة مسار التدفق (`ProcessFlow.tsx`)
- مكون بصري فقط، يستخدم `useEffect` مع مؤقت دوري لنقل التوهج بين المراحل. 

### د. الموازين الحية (`LiveGauges.tsx`)
- **العناصر:** 4 مقاييس دائرية (Dial Gauges) تعتمد على SVG و Stroke-Dasharray لحساب نسبة الامتلاء.
- **البيانات:** كل مقياس يستقبل (قيمة حالية، قيمة مستهدفة). إذا القيمة الحالية = المستهدفة يتحول المؤشر للأخضر.

### هـ. المخطط المباشر (`PlantMap.tsx` / `ScadaPlantConsole.tsx`)
- شاشة معقدة تعرض MIMIC Diagram.
- **الأزرار:** أزرار Toggle للتحويل بين وضع التحكم (Auto / Manual) لكل ذراع أو بوابة (تستدعي API لكتابة Coils في ה-PLC).

## 4. صفحة الإنتاج (Production Page & BatchForm)
**المسار:** `/system/operator/production/page.tsx`
- **`BatchForm.tsx` (نموذج الإنتاج):** هو المكون الأكثر خطورة في النظام.
- **حقل اختيار الطلب:** يعرض فقط الطلبات الجاهزة. عند التغيير، يُحدث حالة `selectedOrderId`.
- **حقول الشاحنة والسائق:** `useState` بسيطة. يتم التحقق من وجودها لمنع التشغيل الخاطئ.
- **بطاقة "ملخص ما قبل الإنتاج":** تظهر برمجياً (`Conditional Rendering`) إذا اكتملت جميع الحقول.
- **زر "إطلاق دفعة الخلط":**
  - **الاسم:** `handleBatch`.
  - **الوظيفة:** زر `Submit` يستدعي Server Action أو API.
  - **الـ State اللي يغيرها:** يغير `loading` إلى `true`، مما يعطل الزر (يغير الأيقونة إلى `Activity spin`) لمنع إرسال أمر الخلط مرتين لنفس الشاحنة.
  - **التأثيرات:** يظهر Toast إشعار بنجاح الإرسال، ثم يُصفر الحقول لتستعد للدفعة القادمة.

## 5. صفحة المواد والصوامع (Materials Page)
**المسار:** `/system/operator/materials/page.tsx`
- **`ScadaSiloSVG.tsx`:** 
  - يعرض SVG تفاعلي.
  - **حساب الأيام المتبقية:** المعادلة المضمنة هي:
    `Math.round(stock / (maxCapacity * 0.05))` كقيمة افتراضية (افتراض استهلاك 5% يومياً). يتم عرض النص "يكفي لـ X يوم". إذا كان `stock = 0` يطبع "فارغ — تعبئة فورية".

## 6. الجداول والـ Widgets (Tables & Cards)
- **`TicketListClient.tsx`:**
  - يعرض التذاكر بتصميم البطاقات المكدسة `group bg-slate-900/20`.
  - يعرض شارة زرقاء لرقم التذكرة، وخضراء `font-mono` لكود الخلطة.
- **Card Widget (`op-card`):** كلاس مخصص في `operator.css` يعطي الزجاج الداكن والحدود الفضية الدقيقة لتوفير طابع صناعي فخم.

## 7. الحوارات والنوافذ (Dialogs & Modals)
- تستخدم في واجهة المشغل بشكل محدود جداً، لأن النوافذ المنبثقة تحجب الرؤية عن الإنذارات المهمة. الأفضلية للـ `Toast` (إشعارات عائمة في زاوية الشاشة) أو `Inline Warnings` داخل النموذج نفسه (كما في رسالة "مطلوب" الحمراء تحت حقول الشاحنة).
