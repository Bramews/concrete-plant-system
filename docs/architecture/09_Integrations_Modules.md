# 🔗 الفصل التاسع: تكامل الأنظمة والوحدات (Integrations & Modules)

## 1. وحدة المختبر (Lab Module)
هذه الوحدة هي صمام الأمان للنظام.
- **تكاملها مع الإنتاج:** المشغل لا يمكنه تشغيل خلطة إلا إذا كانت موجودة في المختبر. المختبر يُصدر `LabApproval` يربط بين `Order` وبين `MixDesign`.
- **البيانات المتبادلة:** بمجرد صب الخرسانة وتفريغها، النظام يرسل إشعاراً لوحدة المختبر بأخذ عينة مكعب (Cube Test).
- **الـ Cube Tests:** النظام يتابع عمر المكعب (7 أيام، 28 يوماً) ويطالب بإدخال نتيجة الكسر (MPa). إذا فشل الكسر، يعود الأثر إلى الطلبية وإلى العميل كـ Alert.

## 2. وحدة المبيعات وإدارة الطلبات (Sales & Order Management)
- **دورة الطلب:**
  1. موظف المبيعات يتفق مع العميل، وينشئ `Order` بحجم 100 م³.
  2. يحدد المشروع (`Project`).
  3. يوافق المختبر.
  4. المشغل ينتج.
  5. المبيعات يراقبون شريط التقدم (Progress Bar) من 0% إلى 100% في شاشتهم لحظة بلحظة ليعرفوا متى تنتهي الطلبية ويتم إرسال الفاتورة.

## 3. وحدة المحاسبة وإصدار الفواتير (Accounting & Invoicing)
- **لا تكرار للبيانات:** عندما يطبع المشغل `DeliveryTicket`، النظام آلياً يرسل الحدث إلى `LedgerEntry` (دفتر الأستاذ) وإلى نموذج `Invoice` (الفاتورة).
- **احتساب التكاليف آلياً (Automated Costing):** الفاتورة لا تُحسب على التكلفة التقديرية، بل تُحسب بناءً على حقل `actualMixData` (المواد المصبوبة فعلياً التي سحبها الـ PLC)، مما يضمن عدم خسارة الشركة لقرش واحد بسبب زيادة الإسمنت.

## 4. التكامل مع إدارة المخزون (Inventory Sync)
- **نقطة إعادة الطلب (Reorder Level):** 
  - عندما يسحب المشغل أسمنت، وينخفض رصيد الصومعة إلى أقل من 20%، النظام يرسل إشعاراً (SystemAlert) آلياً إلى قسم المشتريات لتوجيه شاحنات أكياس أسمنت جديدة للمصنع (IncomingShipments).

## 5. التكامل الخارجي (External API / GPS)
- **تتبع الشاحنات (Truck Tracking):** جدول `DeliveryTicket` يحتوي على حقول `currentLat` و `currentLng` و `trackingToken`. يمكن للسائق أو نظام GPS خارجي تحديث هذه الحقول ليقوم النظام برسم موقع الشاحنة على خريطة للمشغل ومدير المبيعات.
- **بوابات الدفع:** للمصانع التي تقبل دفع إلكتروني، يرتبط نموذج `Payment` ببوابات دفع مثل Stripe (حقل `stripeId`).
