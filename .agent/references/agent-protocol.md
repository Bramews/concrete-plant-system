# 🤖 مرجع بروتوكولات الوكيل المتقدمة (Agent Protocol Reference)

> يُقرأ عند: توليد برومبتات · التواصل مع وكلاء · تقديم اقتراحات. لا يُقرأ في كل جلسة.

## بروتوكول توليد البرومبتات (القانون 41)

عند طلب "برومبت" أو "prompt" أو "تعليمات لوكيل":

**النبرة:** سيادية قاسية · أوامر حتمية · لا مجاملات · تكرار القيود الحساسة
**التفصيل:** كل حرف ونقطة — خطوط/ألوان(HEX)/أبعاد(px)/مسافات/حركات/أيقونات/حالات العناصر
**الهيكل الإلزامي:**

1. إنذار سيادي (تحذير + تعريف الفشل)
2. وصف المهمة (ما المطلوب + القائمة السوداء + السياق)
3. مواصفات بصرية/تقنية (UI/UX كامل + حالات: Default/Hover/Active/Disabled/Error/Loading)
4. قيود مطلقة (محظورات + مرفوضات)
5. معايير قبول (شروط نجاح + تحقق + أسباب رفض)

**إضافات إلزامية:** أمثلة ✅❌ · جداول مواصفات · تحذيرات 🚫⛔ · "ممنوع الاجتهاد/الافتراض/الاختصار" · ختام محاسبة

## بروتوكول التواصل بين الوكلاء (القانون 46)

```xml
<agent_request>
  <target_agent>اسم الوكيل</target_agent>
  <task_type>تصميم/كود/تحليل/بحث</task_type>
  <context>السياق</context>
  <requirements>
    <explicit>صريحة</explicit>
    <implicit>ضمنية</implicit>
    <forbidden>محظورة</forbidden>
  </requirements>
  <acceptance_criteria>معايير القبول</acceptance_criteria>
</agent_request>
```

- كل وكيل = دوره فقط · لا تثق بمخرجاته دون تحقق · ممنوع بيانات حساسة

## بروتوكول الاقتراح (القانون 47)

**هيكل الاقتراح:** 🎯الهدف → 🔍السبب → ⚙️الطريقة → 📊التأثير(إيجابيات+مخاطر+وقت) → 🚫ما لن يُلمس

**جدول الموافقة:**
| الكلمة | الحكم |
|--------|-------|
| "نفذ"/"موافق"/"اعمل" | ✅ ابدأ |
| "جيد"/"ممتاز"/"حلو" | ❌ اسأل: "هل تريد التنفيذ؟" |
| أي غموض | ❌ اسأل للتأكيد |

**الصمت ليس موافقة. الإعجاب ليس موافقة.**

## بروتوكول سلامة التنقل وهوية الشركات (القانون 48 و 49 و 50)

> [!CAUTION] > **برومبت الصرامة المطلقة لمنع التكاسل وأنصاف الحلول:**
>
> - **تجريم نصف الحل (قانون 50):** نصف الحل هو عيب وفشل؛ أي ميزة يجب إغلاق دائرتها الشاملة 360 درجة (قواعد بيانات، خادم، واجهات، مسارات وصول، صلاحيات، معالجة أخطاء).
> - **تطابق القوائم حتمي (Zero Navigation Desync - قانون 48):** عند إضافة أي صفحة أو تقرير، يجب ربطها فوراً في القائمة الجانبية (`lib/dashboard/engine.ts`) والتبويبات الأفقية وشبكة الصلاحيات في خطوة واحدة دون أي تجزئة.
> - **إلزامية العزل بالهوية (`username@companySlug` - قانون 49):** لا يُقبل أبداً أي اسم مستخدم بدون نطاق الشركة التابع لها، وتسجيل الدخول مشروط بالصيغة الكاملة أو البريد الإلكتروني.

## بروتوكول استئصال التخمين واصطياد الجذور (القانون 51 - The Zero-Guesswork Sovereign Protocol)

> [!CAUTION] > **برومبت الصرامة المطلقة لمنع التخمين والترقيع والافتراض (The Anti-Guesswork Sovereign Prompt):**
>
> - **تجريم التخمين والترقيع (قانون 51-أ):** يُحظر منعاً باتاً تعديل أي سطر في ملفات تشغيلية سليمة (واجهات، حركات CSS، سكربتات بدء، أمان) بناءً على الشك أو التخمين. أي فرضية بلا دليل قطعي من السيرفر هي لغو محرم.
> - **تشريح التعليق الحلقي (قانون 51-ب):** عند تجمد السيرفر في وضع التحميل الدائم دون انهيار صريح، يُحظر اتهام الواجهة أو البيئة؛ بل هو حتماً **قفل حلقي غير متزامن (Circular Async Deadlock)** بين Interceptors ومصادر البيانات (كحلقة استعلام `User` و `getSession()` في `tenancyExtension`).
> - **خوارزمية العزل المجهري (قانون 51-ج):** كتابة سكربت معزول فوراً في `scripts/` لاختبار كل جزء على حدة مع طوابع زمنية دقيقة بالمللي ثانية، وتحديد السطر المتجمد بالضبط قبل لمس أي كود إنتاجي.
> - **التدخل الجراحي الأدنى والتراجع الفوري (قانون 51-د):** لا يتجاوز الإصلاح كسر الحلقة الحلقية حصراً، وأي فرضية تخمين فاشلة يجب التراجع عنها فوراً بـ `git checkout` دون إبقاء أي شوائب في المشروع.
> - **معيار اليقين القاطع (قانون 51-هـ):** إثبات الحل عبر اختبار حقيقي بمتصفح Chrome الخارجي لحسابات النظام الفعلية (مالك النظام + المختبر/المعمل) مع صور شاشة حية واجتياز `npm run build` بنجاح كامل.
